Die Abizeitung in Gefahr

📰 Zwei Wochen vor der Druckabgabe. Alle Fotos, Steckbriefe und Layouts der Abizeitung liegen auf einer externen Festplatte. Seit heute Morgen macht sie merkwürdige Klickgeräusche …

Festplatten sind Verschleißteile: In großen Rechenzentren fallen pro Jahr etwa 1 bis 2 von 100 Platten aus. Das Abi-Komitee fragt euch deshalb um Rat:

❓ Wie speichern wir die Abizeitung so, dass der Ausfall einer Festplatte egal ist?

Um das zu klären, verfolgt ihr in dieser Stunde einen Text bis aufs einzelne Bit – und verteilt ihn auf mehrere Festplatten. Zusammen bilden sie ein RAID.

Teile:

Jedes Zeichen ist eine Zahl

Ein Computer speichert keine Buchstaben, sondern nur Nullen und Einsen. Deshalb bekommt jedes Zeichen eine Nummer aus der ASCII-Tabelle. Diese Nummer wird als Byte gespeichert.

Beispiel: A hat den Code 65 = 64 + 1.

1286432168421
01000001

Also steht A im Speicher als 0100 0001.

Aufgabe E1: Das Zeichen I hat den ASCII-Code 73. Wandle ihn von Hand in eine 8-Bit-Binärzahl um.

I =

73 = 64 + 8 + 1 → Stellen 128 64 32 16 8 4 2 1 ergeben 0 1 0 0 1 0 0 1, also 0100 1001.
Welche der Zahlen 128, 64, 32, 16, 8, 4, 2, 1 stecken in 73?
Zieh von 73 immer die größte Zweierpotenz ab, die noch passt. Für jede Stelle, die passt, schreibst du eine 1, sonst eine 0.
73 − 64 = 9, 9 − 8 = 1, 1 − 1 = 0. Besetze jetzt die Stellen 128 … 1 mit 0 oder 1.
1286432168421
01001001

73 = 64 + 8 + 1. Das Zeichen I wird also als 0100 1001 gespeichert.

Euer Text als Bitfolge

Gebt einen kurzen Text ein (höchstens 12 Zeichen). Er wird sofort in ASCII-Codes und Bytes übersetzt – und genau dieser Text wandert in allen folgenden Teilen auf die Festplatten.

⚠️ Umlaute, ß und Emojis gibt es in ASCII nicht – sie wurden durch „?“ ersetzt.

Tippt einmal „Grüße“ ein. Warum erscheinen Fragezeichen?
💡

Merke: Vom Zeichen zum Bit

ASCII: Zeichentabelle, die jedem Zeichen eine Zahl von 0 bis 127 zuordnet (z. B. A = 65).

Byte: 8 Bit. Ein ASCII-Zeichen belegt ein Byte, z. B. A = 0100 0001.

🔒 Teil 2 – Die Treppenhausschaltung

Gebt das Passwort ein, das an der Tafel steht.

💡

Merke: RAID 0 und RAID 1

RAID 0 (Striping): Die Daten werden in Blöcke aufgeteilt und abwechselnd auf die Platten geschrieben. Vorteil: schnell, volle Kapazität. Nachteil: keine Redundanz – fällt eine Platte aus, sind alle Daten verloren.

RAID 1 (Mirroring): Die Daten werden auf alle Platten gespiegelt. Vorteil: hohe Verfügbarkeit – die Daten bleiben erhalten, solange eine Platte intakt ist. Nachteil: nur die Kapazität einer Platte nutzbar → teuer.

❓ RAID 0 ist günstig, aber unsicher. RAID 1 ist sicher, aber teuer. Geht das sicher und günstig?

Die Idee dafür steckt in einer Schaltung, die ihr aus jedem Treppenhaus kennt.

Teil 3 – Zurück zur Abizeitung

Das nächste RAID nutzt eure Regel. Arbeitet wieder zu zweit, beobachtet und erklärt euch gegenseitig, was passiert.

Teile:

Wie entsteht die Parität?

⚠️ Umlaute, ß und Emojis gibt es in ASCII nicht – sie wurden durch „?“ ersetzt.

Klickt links auf einen Streifen (A, B, C …), um ihn genauer anzusehen. Ein Klick auf den Kopf einer Platte (💽) lässt sie ausfallen.

📝 Eure Beobachtung

Beschreibt, wie der Paritätsblock eines Streifens aus den anderen Blöcken entsteht. Wo liegt die Parität in den verschiedenen Streifen?

Wählt einen Streifen aus und vergleicht die Bits der Datenblöcke spaltenweise mit dem Paritätsblock.
Schaltet „Einsen zählen“ ein. Wann steht in der Parität eine 1, wann eine 0?
Denkt an Teil 2: Welche Verknüpfung liefert 1, wenn die Eingänge verschieden sind?

Der Paritätsblock ist die XOR-Verknüpfung aller Datenblöcke des Streifens (spaltenweise: ungerade Anzahl Einsen → 1). Die Parität liegt nicht immer auf derselben Platte, sondern wandert von Streifen zu Streifen weiter.

Eine Platte fällt aus – ihr rettet die Daten

Scrollt nach oben zum Simulator und klickt auf den Kopf einer Platte. Die fehlenden Zeichen rechnet diesmal kein Computer aus – das macht ihr in der Rettungswerkstatt unter dem Simulator. Rettet mindestens einen Streifen selbst.

🛠️ Noch kein Streifen von euch gerettet.
Welche Bytes des Streifens kennt ihr noch? Die Parität gehört dazu.
Schaltet „Einsen zählen“ ein. Denkt an euren Merksatz aus Teil 2.
Verknüpft alle noch vorhandenen Bytes des Streifens spaltenweise mit XOR: ungerade Anzahl Einsen → 1, gerade → 0.

Das fehlende Byte ist das XOR aller übrigen Bytes des Streifens inklusive Parität. Beispiel: Fehlt D2, gilt D2 = D1 ⊕ P (bei 3 Platten) bzw. D2 = D1 ⊕ D3 ⊕ P (bei 4 Platten). Prüft zur Kontrolle, ob das Ergebnis ein sinnvolles Zeichen eures Textes ist.

📝 Erklärt euch gegenseitig

Warum funktioniert die Rettung? Schreibt eure Erklärung in zwei bis drei Sätzen auf.

Was wisst ihr über einen Streifen noch, wenn eine Platte fehlt?
Erinnert euch an euren Merksatz aus Teil 2.
Fehlt ein Block, kennt ihr alle anderen Blöcke und die Parität. Wie hängen sie zusammen?

Die Parität ist das XOR aller Datenblöcke eines Streifens. Fehlt genau ein Block, ist er das XOR aller übrigen Blöcke inklusive Parität – genau wie in Teil 2 aus zwei Werten der dritte folgt.

Merke: RAID 5 (Striping mit verteilter Parität)

Die Paritätsblöcke sind das XOR aller Datenblöcke eines Streifens: P = D1 ⊕ D2 ⊕ …

Die Parität wandert über alle Platten, damit keine Platte zum Flaschenhals wird.

Eine Platte darf ausfallen: Der fehlende Block ist das XOR aller übrigen Blöcke inklusive Parität.

Nutzbar sind (n − 1) von n Platten.

Merke: RAID ist kein Backup

RAID schützt nur vor dem Ausfall von Hardware – nicht vor Datenverlust durch Löschen, Schadsoftware, Brand oder Diebstahl. Dasselbe gilt für die Synchronisation in eine Cloud.
